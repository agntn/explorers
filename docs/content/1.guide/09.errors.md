## The hierarchy

```ts
import {
  ExplorerError,
  HTTPError,
  TransportError,
  AuthError,
  RateLimitError,
  BlockedError,
  PlanRestrictedError,
  NotFoundError,
  UnsupportedChainError,
  UnsupportedOperationError,
  UnknownProviderError,
  AddressChainMismatchError,
} from "@agntn/explorers";
```

| Class                       | When                                                                      | Extra                          |
| --------------------------- | ------------------------------------------------------------------------- | ------------------------------ |
| `HTTPError`                 | a response whose error status no class below claims                       | `statusCode`, `reason`, `rawUrl`, `body` |
| `TransportError`            | no response at all: refused, unresolved host, reset, timeout, abort       | `reason`, `code`, `rawUrl`     |
| `AuthError`                 | credentials missing or rejected, 401, 403                                 |                                |
| `RateLimitError`            | 429 or an explorer saying so in words                                     | `retryAfter` in seconds        |
| `BlockedError`              | a bot wall in front of the explorer, like a Cloudflare challenge page     |                                |
| `PlanRestrictedError`       | valid key, but the read needs a paid tier                                 |                                |
| `NotFoundError`             | 404, an unknown address, hash, block or an ENS name that doesn't resolve  |                                |
| `UnsupportedChainError`     | this provider doesn't serve that chain                                    | `chain`                        |
| `UnsupportedOperationError` | this provider doesn't have that operation                                 | `operation`                    |
| `UnknownProviderError`      | `create()` or `resolveProvider()` asked for a name nobody registered      |                                |
| `AddressChainMismatchError` | the address belongs to another chain family, caught before any request   | `address`, `chain`, `matches`  |

Every one extends `ExplorerError` and carries `provider`, so a `catch` can be as broad or as narrow as you like. `AddressChainMismatchError` leaves `provider` empty, because no provider was asked: a Bitcoin address with `chain: "ethereum"` fails on its format, and `matches` lists the chains that format does fit. `UnknownProviderError` lists the names that are registered, so a typo takes one look to fix, not a search.

```ts
try {
  await provider.getTxDetail?.(hash, "ethereum");
} catch (error) {
  if (error instanceof RateLimitError) {
    console.log(error.retryAfter); // seconds, when the explorer said
  }
  if (error instanceof NotFoundError) {
    // the hash is unknown to this explorer
  }
}
```

## normalizeError

Providers don't write their own classification, they'd all get it slightly differently wrong. `normalizeError(error, provider, url)` turns whatever the shared client, a provider's own check or a custom provider's ofetch call threw into the hierarchy. The first match wins:

- No response at all becomes `TransportError`. Its `reason` is the message of the innermost cause, like `connect ECONNREFUSED 203.0.113.7:443`.
- A response carrying `cf-mitigated: challenge` becomes `BlockedError`, whatever its status.
- 404 or "not found" in the message becomes `NotFoundError`.
- 429 or "rate limit" becomes `RateLimitError`.
- 401, 403 or "unauthorized" becomes `AuthError`.
- Any other status becomes `HTTPError`.

A `TransportError` also carries `code`: `ECONNREFUSED`, `ENOTFOUND`, `TimeoutError` and the like. That's how a refused connection differs from a timeout. An `ExplorerError` passes through untouched. Anything else stays a plain `ExplorerError` with the original message, plus the URL when there is one.

An `HTTPError` message ends with the explorer's own reason when the body gives one, like `HTTP 400 from https://blockstream.info/api/address/1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa/utxo: Too many unspent outputs`. The reason is a plain-text body, or the first `reason`, `detail`, `message`, `error` or `title` field of a JSON one, at the top or one level down. It comes out as one line of at most 200 characters, with no control bytes a terminal would act on. An HTML error page gives no reason, so that message stops at the URL. The quoted text also sits alone in `reason`, for a page or a log line that leaves the URL out. The CLI, MCP, Pi and OMP show only the message, and this is the part that tells you what to change.

## Keys never leak

`ExplorerError`'s constructor runs every message through one redaction: `api_key`, `apikey`, `key`, `secret` and `token` query parameters become `REDACTED`. `HTTPError` does the same to `rawUrl` and to the response body, in case the explorer echoed the request back. Helius carries its key as `api-key` in the query, which is exactly the case this guards. Log an error, paste it in an issue, fine.

## Rate limits

The HTTP client never retries, so a 429 is classified before anything waits. `Provider` then retries that same backend twice. It honors `Retry-After` when the explorer sent one, otherwise it backs off from one second. JSON answers that say "rate limit" in a 200 count as a 429 too, because Etherscan dresses those up as ordinary envelopes.

After that, `withProvider()` still moves an automatic selection once to the next provider that serves the chain. It does that for `RateLimitError`, `BlockedError`, `PlanRestrictedError`, `TransportError` other than your own abort, and an `HTTPError` with a 5xx status. An explicit provider never switches backends.

## Bot walls

Why would a keyless explorer suddenly want a key? It doesn't. Cloudflare sometimes sits in front of a public instance and answers every API call with a 403 and a "Just a moment..." page for browsers. Read as a plain 403, that looked like `Authentication failed`. And off you went, hunting for a key Blockscout never asked for.

Cloudflare marks every challenge page with `cf-mitigated: challenge`, so `normalizeError` checks that header before the status:

```text
Blocked by blockscout: HTTP 403 from https://base.blockscout.com/api/v2/addresses/0x… is a Cloudflare challenge page, which no API key gets past
```

`Provider` doesn't retry a `BlockedError`. A page built for a browser won't turn into JSON after a second of backoff. An automatic selection moves to the next provider instead, and an explicit one hands you the error.
