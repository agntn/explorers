## Address it

```ts
const blockscout = await create("blockscout");
await blockscout.getTokenBalances("0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045", "ethereum", {
  nonZeroOnly: true,
});
```

No key, no configuration. Each chain has its own Blockscout host, `eth.blockscout.com`, `base.blockscout.com` and so on, and the provider picks the host from the chain. Scroll and zkSync are here and not on Etherscan, Berachain and BSC the other way round.

## What it reads

The REST v2 API under `/api/v2`: `/addresses/:address` for the balance, `/addresses/:address/transactions` for history, `/transactions/:hash` for one, `/smart-contracts/:address` for contract metadata, `/addresses/:address/token-balances` for holdings, `/addresses/:address/token-transfers` for transfers, `/stats` for gas and `/blocks/:number` for a block.

## Gotchas

- `/api/v2/addresses/:address/token-balances` returns the complete holding array. A busy wallet makes that several megabytes, so this one read gets sixty seconds unless `ProviderConfig.timeout` overrides it.
- It's the final fallback. `resolveProvider()` returns Blockscout for a chain nobody serves, and the answer is then an `UnsupportedChainError` naming the chain, which beats an unrelated provider's complaint.
- Public instances rate limit generously but not infinitely. A 429 is a `RateLimitError`; with an automatic selection the read moves on once.
