A chain is a key from `@agntn/chains`, so `normalizeChain("btc")`, `normalizeChain("mainnet")` and `normalizeChain("Arbitrum One")` all land on the same canonical name, and a typo throws instead of quietly reading another network. Below, every chain at least one provider claims, straight from `builtins`. A tick means some provider serves the operation on that chain; the [provider pages](/providers) say which one and with what key.

## Reading the table

- **Two providers on one chain** means a fallback exists. Ethereum and Bitcoin have three each, and a rate limit, no answer or a 5xx on the first moves the read to the next one, once.
- **One provider** means an outage on that explorer is your outage. Solana has two only if you count Helius, which has no balance endpoint.
- **A row without ticks** is Aptos. The provider is registered, its capabilities are all false and the required methods throw `UnsupportedOperationError`. That's deliberate and the [Aptos page](/providers/aptos) says why.
- **Unspent outputs** come from Mempool and Blockstream on the Bitcoin family from WhatsOnChain on Bitcoin SV and from Blockbook on Bitcoin Gold, and nowhere else. Decred is a UTXO chain too, but dcrdata doesn't serve them yet, so its tick stays off.
- **Decimals differ.** `balance` is a string in the smallest unit; `formatWei(value, decimals)` needs `8` for BTC, BSV, BTG, ZEC and DCR, `9` for SOL, `12` for AR, `6` for ADA, `7` for XLM and the token's own value for everything else. Nothing on this site rounds a raw amount.

## Aliases that work

`normalizeChain()` takes the display name, the key and the aliases people actually type: `eth`, `mainnet`, `arb`, `op`, `matic`, `btc`, `bsv`, `btg`, `zec`, `ltc`, `sol`, `apt`, `dcr`, `xlm`, `coinbase` for Base. Missing input defaults to `ethereum`. The empty string throws.
